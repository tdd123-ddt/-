# STORY.md — 医护洞察与温度指引引擎 · 比赛答辩

## ① 用户意图对齐

- **目标受众**：比赛评审（AI 编程赛初赛评委，可能是技术评委 + 业务评委混合），答辩/评审场合。
- **核心目标**：让评委相信三点——①方案完整（四模块全链路 + 触达 + 合规）；②效果可验证（KR1 硬指标达标、b/c/d 有真实数字）；③不是纯模板/伪 AI（每个数字可溯源、AI 原生度高）。
- **PPT 长度**：12 页（2-3 个 Hero 页）。
- **视觉调性**：科技克制 / 数据驱动 / 医疗温度 / 严谨可信。
- **内容边界**：必讲——定位、架构、四模块效果数字、触达闭环合规、AI 原生度自证；不讲——代码细节、环境配置琐事；禁碰——伪造专家一致率等未经证实的数字。

12 页 = 封面(hero) + 目录 + 3 章节(每章 section 扉页 + 2-3 内容页) + 结束页(hero)

**非对称版式预算**（≥40%）：04 左标题+右内容、05 非对称双栏、07 巨型数字+洞察、08 左大图+右文字、09 非对称双栏、11 非对称双栏 → 6/12 = 50% ✅
